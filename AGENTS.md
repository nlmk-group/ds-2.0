# AGENTS.md — правила для AI-агентов и контрибьюторов

Каноничный свод правил репозитория `@nlmk/ds-2.0`. Файл читают Claude Code, Codex, Cursor, Copilot и другие агенты, а также люди. Если правило здесь противоречит тому, что агент «привык» делать — приоритет у этого файла.

## Проект

React 19 + TypeScript компонентная библиотека (`@nlmk/ds-2.0`). ~75 компонентов, CSS-токены (light/dark), Storybook 10, Jest + React Testing Library, Vite.

## Конвенции кода

- Компоненты: PascalCase (`Button`, `TimePicker`)
- Интерфейсы: префикс `I` (`IButtonProps`)
- Enum'ы: префикс `E` (`EButtonSize`, `EButtonVariant`)
- Модули стилей: `Component.module.scss`, классы camelCase
- Типы — в `types.ts`, enum'ы — в `enums.ts` рядом с компонентом
- `forwardRef` для всех компонентов, пробрасывающих DOM-элемент
- Комментарии и JSDoc — на русском
- Цвета, отступы, радиусы, тени — только токенами из `public/css/tokens/`, хардкод запрещён

## Структура компонента

```
src/components/ComponentName/
├── ComponentName.tsx          # Основной компонент
├── ComponentName.module.scss  # Стили
├── types.ts                   # Интерфейсы и типы
├── enums.ts                   # Enum'ы
├── index.ts                   # Реэкспорт
├── ComponentName.test.tsx     # Тесты
├── subcomponents/             # Вложенные компоненты (если есть)
└── _stories/
    ├── ComponentName.stories.tsx
    ├── ComponentName.mdx
    ├── Stories.tsx
    └── argsTypes.tsx
```

Имя папки = имя экспортируемого компонента. Единственное отклонение — `Illustrations/` при компоненте `Illustration`: имя папки опубликовано как подпуть `@nlmk/ds-2.0/Illustrations` в `exports` пакета, поэтому переименование сломает потребителей и делается только мажором. Внутри всё остальное уже названо правильно (`Illustration.test.tsx`, `Illustration.stories.tsx`, `Components/Illustration/…`).

Тесты и истории обязательны для каждого нового компонента.

## Именование историй Storybook

Названия историй — это навигация по документации и то, что видит потребитель библиотеки. Разнобой ломает и поиск по сайдбару, и восприятие.

### Заголовки разделов

| Файл | Значение |
|---|---|
| `ComponentName.stories.tsx` | `title: 'Components/<ComponentName>/Stories'` |
| `ComponentName.mdx` | `title="Components/<ComponentName>/Info"` |

- `<ComponentName>` — ровно имя экспортируемого компонента, латиницей, PascalCase.
- Префикс `Components/` обязателен: без него раздел уезжает в корень навигации.
- У компонента должны быть **обе** страницы — `Info` (MDX) и `Stories`.

Осознанные исключения, менять их не нужно:

| Раздел | Отклонение | Почему |
|---|---|---|
| `Table` | `title: 'Table/Stories'` без префикса, MDX нет, названия историй по-русски («Таблица с закреплённым заголовком») | Таблица — отдельный организм со сложными составными примерами, её держим самостоятельным разделом верхнего уровня; страница `Info` для неё избыточна, а русские названия точнее описывают составные сценарии. **Названия историй Table на латиницу не переводим** |
| `Select` | есть только `Select.mdx`, историй нет | Компонент deprecated. Новые истории для него не заводим — актуальные живут в `SimpleSelect` и `MultiSelect` |

### Название истории (`storyName`)

`storyName` обязателен у каждой экспортируемой истории. Формула:

```
<ComponentName> <описание на русском>
```

**Имя компонента — латиницей, всё остальное — по-русски.**

- Не переводим: `Modal по умолчанию`, а не «Модальное окно по умолчанию».
- Не сокращаем и не переставляем: `ToggleButtonGroup`, а не «Toggle Button»; `SkeletonLoader`, а не «Skeleton loader».
- Не выдумываем имён, которых нет в коде. Если такого экспорта в библиотеке не существует, потребитель не найдёт его ни поиском по сайдбару, ни в типах.

#### Какое имя ставить: то, что история показывает

Имя в названии — это имя того, что история демонстрирует **как главный объект**, а оно не обязано совпадать с именем файла историй. Три законных случая, когда они расходятся:

| Случай | Пример | Почему так |
|---|---|---|
| Подкомпонент | `File по умолчанию` в `AttachFiles.stories.tsx` | История рендерит `<File>` из `AttachFiles/subcomponents` напрямую, с `IFileProps`, без обёртки `<AttachFiles>`. Показываем подкомпонент — называем подкомпонентом |
| Режим со своим DOM-элементом | `Textarea с лейблом` в `Input.stories.tsx` | Под капотом реальный `<textarea>`. Разработчик ищет по тому слову, которое знает |
| Семейство компонентов | `Select с поиском` в `SimpleSelect.stories.tsx` | `Select`, `SimpleSelect` и `MultiSelect` — одно семейство селектов, а сам `Select` давно deprecated |

Правило простое: **как только история начинает рендерить другой объект — меняется и имя в названии**. В `AttachFiles.stories.tsx` первые четыре истории показывают одиночный `<File>` и названы `File …`, остальные пять оборачивают его в `<AttachFiles>` и названы `AttachFiles …` — это правильно, а не разнобой.

Что под исключение **не** попадает: имя пропа, имя внутреннего состояния или выдуманное имя вместо реального компонента.

### Первая история

Всегда `<ComponentName> по умолчанию`.

Именно «**по умолчанию**» — не «дефолтный», не «Default», не «Базовый». Документацию читают в том числе люди без английского, и «дефолтный» им ничего не говорит. У каждого компонента такая история должна быть: попадать сразу в частный кейс нельзя.

### Остальные истории

Шаблоны, по убыванию частоты:

| Шаблон | Пример |
|---|---|
| `<ComponentName> с <чем-то>` | `Input с иконкой слева` |
| `<ComponentName> в состоянии <...>` | `MultiSelect в состоянии error` |
| `<ComponentName> без <...>` | `Drawer без крестика` |
| `<ComponentName> <прилагательное>` | `Splitter вертикальный` |
| `Варианты <чего-то> <ComponentName>` | `Варианты цветов Checkbox` |

Чего не делаем:

- **Не опускаем имя компонента.** «Колонки равной ширины» → `Grid с колонками равной ширины`. Без имени история теряется в общем поиске по сайдбару: непонятно, к какому компоненту она относится.
- **Не ставим двоеточие** как разделитель: `Comments с вложенными ответами`, а не «Comments: комментарий с вложенными ответами».
- **Не выносим прилагательное вперёд**: `Splitter вертикальный с начальными размерами`, а не «Вертикальный Splitter …».
- **Не начинаем со слова «Пример»** — история и так пример.
- **Без технических подробностей реализации в названии**: «Spinner где Icon, как children (JSX.Element)» → `Spinner с иконкой вместо индикатора`. Тип пропа объясняют argTypes и MDX, а не название.
- Без точки в конце, без заглавных букв в середине (кроме имён компонентов и пропов).

#### Понятность важнее формы

Шаблоны выше — это умолчание, а не смирительная рубашка. Если история показывает не свойство компонента, а **поведение или сценарий**, и описательная формулировка объясняет его короче и яснее — берём её, даже если получается целое предложение:

- `Открытие модального окна убирает скролл на странице` — понятнее, чем `Modal с блокировкой скролла страницы`
- `Отображение PDF`, `Сборка панели с Header`, `Кнопки-иконки`, `Один таб с наглядными контролами` — сразу ясно, что внутри

Критерий один: **читатель должен понять, что увидит, не открывая историю**. Если шаблонное название этого не даёт — пишем словами. Это не отменяет остального: имя компонента, кириллица и запрет на двоеточие действуют всегда.

### Имена экспортов

```
export const <ComponentName><Модификатор>
```

- PascalCase, первая история — `<ComponentName>Default`.
- Модификатор **после** имени компонента: `SwitchDisabled`, а не `DisabledSwitch`.
- Без camelCase (`dndDefault`), без сокращений (`BtnGroupSizes`), без суффикса `Example`.
- Для истории подкомпонента берём имя подкомпонента: `FileDefault`, а не `AttachFilesDefault`.

### Типографика

- Кириллическая «**с**», а не латинская `c`. То же для омоглифов `а е о р х у`: латинская буква внутри русского слова ломает поиск по сайдбару — историю не найти, набрав её название.
- Без двойных и висячих пробелов.

### Пример эталонной истории

```tsx
const meta: Meta<IStatusProps> = {
  title: 'Components/Status/Stories',
  component: Status,
  argTypes: argsTypes
};

export default meta;

export const StatusDefault = (props: IStatusProps): JSX.Element => (
  <Status {...props}>{props.children}</Status>
);
StatusDefault.storyName = 'Status по умолчанию';

export const StatusColors = (props: IStatusProps): JSX.Element => (/* … */);
StatusColors.storyName = 'Status с разными цветами';
```

Живые образцы: `src/components/Status/_stories`, `src/components/Divider/_stories`, `src/components/MultiSelect/_stories`.

> Часть исторических файлов ещё не приведена к этим правилам. При правке такого файла приводим названия в нём целиком, а не только затронутую историю.

## Токены и темы

- Исходники: `tokens.json`, `typographyTokens.json` (генерируются, в git не лежат)
- CSS: `public/css/tokens/` — light, dark, typography, shadows, radius
- Генерация: `yarn token:generate`
- Тема переключается компонентом `<Theme>` и хуком `useThemeSwitcher`

## Команды

```bash
yarn start              # Dev-сервер
yarn test               # Тесты (watch)
yarn test:ci            # Тесты (CI)
yarn lint               # ESLint + tsc
yarn storybook          # Storybook на :6006
yarn build              # Сборка библиотеки
yarn token:generate     # Генерация токенов
```

Перед завершением работы прогоняем `yarn lint` и `yarn test:ci`.

## Коммиты и PR

- Conventional commits со **обязательным** scope — номером задачи: `feat(DESIGNSYS-9999): add new component`
- Типы: `feat`, `fix`, `build`, `docs`, `style`, `refactor`, `perf`, `ci`, `test`, `chore`
- Заголовок коммита — **не длиннее 72 символов** (проверяется commitlint, конфиг в `commitlinterrc.json`)
- Pull request открываем в ветку `dev`, не в `main`
